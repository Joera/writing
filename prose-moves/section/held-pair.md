# Held pair

## Use when
- Two things are both true and pull against each other, and the honest position is to keep both (the protocol must be upgradable while young; an upgradable protocol has governors who could misuse it).
- Resolving the tension would overstate the text's certainty.

## Don't use when
- One side is clearly right and the text knows it.
- The document's certainty is flat and polemical.

## Conflicts with
- [remedy-list](remedy-list.md) as the closing of the same section.

## Tags
`certainty: open, holds ambiguity` (works in `flat, with limits` when the tension is a stated limit).

## Safe or adds
Safe.

## The move
State both sides in parallel, with equal weight and in the same plain voice. Say why each is true. Do not rank them. Close on what follows from holding both, which is often a commitment rather than a resolution.

## Before
> The upgrade path is kept for maturation, not for control. A protocol that must grow into a working user experience has to be able to change while it is young, and you cannot battle-test an interface you can never amend. But a version with no upgrade path at all, one its own governors could not alter, is possible to build, and this protocol would be glad to be its inspiration.

## After
> The upgrade path is kept so the protocol can mature. A protocol that must grow into a working user experience has to be able to change while it is young, and an interface that can never be amended cannot be tested against real use. An upgrade path is also a lever, and whoever governs it holds one. Both are true. What this paper commits to is that every use of that lever is public, and that a version with no upgrade path at all is possible to build.

*(Also fixes the stray "you" and the protocol "would be glad".)*

## Pitfalls
- A false balance where one side is a straw man.
- Holding a pair the reader needed resolved.
